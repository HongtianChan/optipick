### 2. 算法选择

**问题类型**：集合覆盖问题（Set Cover Problem）

**复杂度**：NP-hard，不可能 O(1) 最优解

**推荐算法**：
- 小规模（n ≤ 10）：回溯搜索（精确解）
- 中等规模（n > 10）：贪心算法（近似解）或回溯 + 剪枝
- 大规模：贪心算法或启发式方法

**理论下界**：ln n 级别的近似比（贪心算法）

### 3. UI 设计理解

**主界面**（第4页）：
- 参数输入：m, n, k, j, s
- 选择模式：随机 n / 手动输入 n
- Values input：显示选中的 n 个数字
- results：显示计算出的 k=6 组
- User input：手动输入 n 个数字的区域

**数据库界面**（第5页）：
- 文件列表：显示所有保存的 DB 文件名
- Display/Delete：显示或删除文件
- 结果显示区：显示选中文件的内容（所有 k=6 组）

## 关键理解

### E.g. 5 为什么是 4 组

- 有 28 个 j=6 组合（8C6 = 28）
- 对每个 j=6 组合，需要至少一个 s=5 组合被覆盖
- 如果 k=6 组和 j=6 组合的交集 ≥ 5 个元素，就满足要求
- 通过算法验证：最少需要 4 组
- 答案可能不同，但数量一定一样

### 算法验证过程

不是从 j=6 组合中选，而是：
1. 列出所有可能的 k=6 组（28 个）
2. 从这 28 个中选最少的几个
3. 让它们覆盖所有 28 个 j=6 组合的要求
4. 通过算法验证最少需要几个

### j=s 和 j≠s 的区别

- **j = s**：要求"所有"（ALL），每个 j 组合的所有 s 组合都要被覆盖
- **j ≠ s**：要求"至少一个"（at least ONE），每个 j 组合至少有一个 s 组合被覆盖
